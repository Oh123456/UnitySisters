# 키트리·인풋버퍼 작업 중단 및 재개 기록

기록일: 2026-11-03. 공격 애니메이션이 현재 한 종류여서 사용자 요청으로 기능 개발을 일시 중단한다. 새 애니메이션이나 공격 데이터를 임의로 추가하지 않는다.

## 현재 판단

키트리 입력 해석, 애니메이션 이벤트에 따른 선입력 수집·소비, 플레이 중 트리 관찰을 연결했다. 사용자가 코드 작성을 통과 처리했지만 평가는 약 5/10이며, 현재 방향을 유지하는 출발점이다. 완성된 설계나 모든 상황에서 검증된 전투 시스템으로 간주하지 않는다.

현재 커맨드는 `Attack`, `Up → Attack`, `(Up | Right) → Attack` 세 가지다. 모두 같은 `AttackCommandBehavior`로 기존 `CharacterCommand.isAttackButton`을 설정하고 같은 기본 공격과 모션을 사용한다. 서로 다른 모션의 다단 콤보, 공격 종류별 요청 전달, 콤보 단계 관리가 완성된 상태는 아니다. 트리의 말단에는 실행 비헤이비어가 있으며, 실행으로 이어지지 않던 작업 중 가지는 제거했다.

## 실행 흐름과 책임

1. `PlayerControllerInputs`가 입력 콜백에서 큐를 기록한다. 조작 캐릭터의 `CommandTree`가 입력 해석 명세다.
2. `PlayerController.FixedUpdate`가 일반 구간의 큐를 소비하고 트리를 탐색한다. 불일치 입력을 건너뛰는 기존 오차 허용 정책과 Flags의 정확한 값 비교를 유지한다.
3. 마지막으로 성립한 비헤이비어가 `CharacterCommand`에 행동 의도를 기록한다. 명령에 StateID를 넣지 않는다.
4. `Character.ExecuteCommand`와 FSM이 현재 실행 가능 여부를 판단한다. 거절한 요청은 소비하며 자동 재시도하지 않는다.
5. 기존 공격 애니메이션 이벤트 → 기능 인터페이스 → 공격 판정 흐름을 사용한다.

`ICharacterFSMCotnroller`는 기존 FSM 컴포넌트의 계약으로 유지했다. 공유 `AttackState`가 owner 인터페이스로 선입력 허용과 종료 정책을 수행한다. 캐릭터별 구간·완료 정보는 `CharacterFSMModel`에 있고, 공유 State에 가변 정보를 저장하지 않는다. Character에 별도 선입력·완료 인터페이스를 추가하지 않았다.

## 선입력과 방향 유지

- 일반 구간은 FixedUpdate마다 판정·소비한다. 렌더 프레임과 처리 주기는 다르다.
- 애니메이션 이벤트의 `Begin`에서 선입력을 시작하고 `End`에서 큐 개수를 확정한다. 이후 입력은 다음 소비 묶음으로 분리한다. `Cancel`은 입력을 폐기한다.
- 정상 공격 완료는 확정 입력을 보존하며, 공격 중단이나 조작 해제는 취소한다.
- 방향 변화 이벤트가 이전 주기에 소비됐어도 공격 시점에 유지하는 방향을 함께 기록한다. 같은 묶음에 기록된 방향을 공격 때문에 중복 추가하지 않으며, End 이후 묶음은 별도의 방향 문맥을 가진다.
- 구간 내 입력에 종전의 0.5초 만료를 적용하지 않는다. 장기 입력 이력이나 매 프레임 방향 반복 수집은 추가하지 않았다.
- `SetDefaultState`의 정상 완료 문맥은 현재 지연 0인 복귀 전이를 전제로 한다. 지연 전이에서는 실제 Exit 전에 문맥이 해제되므로 정상 완료 입력 보존을 지원한다고 가정하면 안 된다. 지연을 도입할 때 기존 FSM 흐름에 맞춰 재검토한다.

## 연결된 자산

- 캐릭터: `UnitySisters/Assets/Resources/SD_Unity_Chan.prefab`
- 입력 명세: `UnitySisters/Assets/Datas/CommandList/UnitySistersCommandData.asset`
- Animator: `UnitySisters/Assets/Resources/SD_Unity_Chan.controller`
- 실제 애니메이션 이벤트: `UnitySisters/Assets/Samples/AnimationEvent/Data/AnimationEventData.asset`

이벤트 데이터에는 기존 공격 판정(FistAttack, 정규화 시간 약 0.3666), Begin(0.45), End(0.95), 기존 공격 종료(0.95)가 들어 있다. 실제 Animator의 Attack과 New State가 같은 이벤트 데이터 GUID를 참조하므로 재개 시 두 참조와 이벤트 의미를 함께 확인한다. 선입력 Begin은 State의 허용 여부로 제한한다.

Samples 전체는 여전히 Git 제외 대상이다. 현재 동작 재현에 필요한 위 이벤트 에셋과 `.meta`만 명시적으로 추적해 커밋에 포함한다. Samples 전체를 추가하지 않는다. 게임 데이터 경로로의 이동은 이번 중단 작업에서 수행하지 않았으며, 나중에 이동한다면 GUID와 Animator 참조를 보존한다.

`stateVersion`, 강제 `Animator.Play`, 새로운 애니메이션 파라미터·전이 보정은 추가하지 않았다.

## 트리 에디터

- 프레임워크 창: `UnitySisters/Assets/Plugins/Framework/Editor/CommandTree/CommandTreeEditorWindow.cs`
- 그래프: 같은 폴더의 `CommandTreeGraphView.cs`
- 게임 연결: `UnitySisters/Assets/Editor/CommandTreePlayModeObserver.cs`
- 메뉴: `UnityFramework/Command Tree/Editor`

편집 모드에서는 에셋 수정·추가·삭제·저장이 가능하다. 플레이 관찰 모드에서는 PlayerController가 붙은 오브젝트 선택 시 조작 캐릭터의 실제 트리를 표시한다. 데이터 선택과 상세 수정, 추가·삭제, 컨텍스트 메뉴, Delete 및 Ctrl+S 경로를 잠근다. 노드 조회·이동·확대는 가능하다. 플레이 종료 시 이전 편집 에셋으로 돌아온다.

실제로 방문한 경로와 노드는 주황색, 마지막 성립 커맨드는 초록색이다. 성립은 FSM의 실행 승인과 다르다. 선입력 수집 중 예상 경로를 별도로 재해석하는 기능은 아니며, 실제 소비 시 탐색 결과를 표시한다. 복합 키는 `Up | Right`처럼 표시한다.

관찰 호출은 `[Conditional("UNITY_EDITOR")]`로 연결하고, private 관찰 연결에 필요한 리플렉션과 노드 경로 매핑은 에디터 코드에서 수행한다. 런타임 필드를 public으로 바꾸지 않았다. 에디터 심볼 없이 실제 탐색 메서드를 분리 컴파일한 IL에서 관찰 호출이 0개인 것을 확인했다. 이는 전체 플레이어 빌드를 수행한 결과는 아니다.

## 검증 범위와 남은 불확실성

마지막 수정 후 Unity 컴파일 오류 0개, `git diff --check` 통과. 검증 종료 시 플레이 중이 아니며 씬은 dirty 상태가 아니었다.

- 실제 명세 에셋과 실제 공격·해제 콜백 및 처리 메서드를 호출한 유지 방향·해제·대각선·중복 억제·선입력 묶음 경계·취소 검증 18개 통과. 방향 설정은 MovePerformed가 사용하는 수집 메서드로 주입했다.
- 플레이 관찰 모드의 편집 차단·선택·컨텍스트 메뉴·단축키·실제 에셋 미변경 검증 15개 통과.
- 실제 명세 에셋의 메모리 복제본으로 편집 모드 추가·삭제 및 편집 에셋 기억 검증 5개 통과.
- 플레이 종료 후 편집 모드·기존 에셋·버튼 복구, 관찰 해제를 확인했다. 실제 유지 방향 공격의 관찰 경로가 Up → Attack인 것도 확인했다.
- 이전 시점에 기본 공격·선입력 재공격과 공유 State의 캐릭터별 독립성을 확인한 기록이 있으나, 이후 가상 입력 장치 자동 검증은 입력 미전달로 시간 초과됐다. 이전 성공 기록을 최종 전체 플레이 검증으로 대체하지 않는다.
- 물리 장치 입력 → 입력 콜백 → FixedUpdate → 실행 승인 → 애니메이션까지의 최종 통합 검증은 미완료다. 새로운 모션을 연결한 콤보 체감 검증도 하지 않았다.
- 앞서 실행한 기존 EditMode 테스트는 35개 중 34개 통과, `FSMData_RejectsStateIDTypeMissingAnExistingID`의 null 값에 대한 Is.Empty 검사 실패 1개가 있었다. 이 실패는 이번 기능에서 수정하지 않았으며, 마지막 수정 후 전체 테스트를 다시 실행했다고 주장하지 않는다.

검증 스크립트와 일부 이전 결과는 로컬 `.utmp`에 있으며 커밋 대상이 아니다. 이 문서가 재개 시 참조할 검증 요약이다.

## 재개 순서

1. 현재 브랜치와 실제 코드·프리팹·Animator·이벤트 데이터 참조를 다시 확인한다. 별도 stash의 이전 실패 구현을 적용하지 않는다.
2. 물리 입력으로 기본 공격, 방향 유지 공격, 대각선, 방향 해제, 선입력 End 시 소비, 피격·조작 해제 시 취소를 실제 관찰 경로와 비교한다. 특히 같은 처리 주기 입력과 방향을 먼저 누른 뒤의 입력을 구분한다.
3. 사용자가 준비한 추가 공격 모션과 공격 데이터, 각 행동의 허용·종료·선입력 시점을 확인한다. 없는 모션이나 데이터를 AI가 만들어 넣지 않는다.
4. 서로 다른 커맨드가 서로 다른 공격을 요청하도록 하는 전달 구조와 애니메이션 연결안을 먼저 보고한다. 지금의 단일 bool 요청이 그대로 공격 종류 선택까지 지원한다고 가정하지 않는다.
5. 승인 후 구현하고, 다단 콤보와 방향 커맨드를 구분해 검증한다. State 공유와 기능 인터페이스 경계를 유지하며 필요성이 확인되지 않은 재생 보정을 추가하지 않는다.

포트폴리오에는 키트리, 애니메이션 이벤트 기반 선입력, 상태별 실행 판단, 에디터 관찰 도구와 발견·수정한 유지 방향 버그를 설명할 수 있다. 다단 콤보 완성 또는 전 범위 런타임 검증 완료로 표현하면 안 된다.
